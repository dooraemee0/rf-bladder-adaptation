# Preprocessing reconciliation

## Finding

The released DER++ checkpoints and the reported validation/test results use
Gaussian smoothing with `axis=0`. For wearable arrays shaped `(channel, time)`,
this smooths across sensor channels, not along depth/time. The 24-hour inference
script independently reimplemented preprocessing with `axis=1`, so its
predictions and derivative figures do not use the preprocessing that produced
the released checkpoints.

No source preprocessing file was modified during this audit. The two paths were
evaluated explicitly as separate experiments with the same fixed checkpoints.

## Call-path audit

### Training and checkpoint selection

`scripts/run_final_gpu*.sh` calls `ablation_A_adaptation.py`, which dispatches
DER++ training in `strategies.py`. Device batches are created by
`ablation_common.make_loader()` using `FolderDatasetUnified` and
`PreprocessTransform`. Validation checkpoint selection calls
`evaluate_and_select_best() -> evaluate()`, which constructs the same dataset
and transform. `PreprocessTransform.__call__()` applies
`gaussian_filter1d(..., sigma=1, axis=0)`.

At this transform boundary, `_load_device()` has already produced separate
horizontal and sagittal arrays with shapes `(3, 2700)` and `(4, 2700)`.
Consequently, `axis=0` mixes neighboring H sensors within the H array and
neighboring S sensors within the S array at each time sample. It is not
depth-axis smoothing.

### Final test tables and figures

`ablation_A_adaptation.run_one()` evaluates the validation-selected checkpoint
once through `ablation_common.evaluate()` on `dev_te` and `clin_te`.
`eval_invitro_final.py` uses the same function to regenerate the reported
cross-domain table values and the prediction CSVs consumed by `plot_fig4.py`.
These reported table and Fig. 4 paths are therefore legacy-compatible
`axis=0` results.

### 24-hour demonstration

`infer_24h.py` duplicates the model and preprocessing rather than importing the
final loader. Its `preprocess_device()` applies Gaussian smoothing with
`axis=1`. `infer_24h_predictions.csv` was generated by that path.
`plot_24h_wear.py` and `plot_24h_150ml_analysis.py` read this CSV, while
`plot_24h_raw_traces.py` also imports the same `axis=1` function. The signal
similarity helper in `plot_24h_150ml_analysis.py` independently uses `axis=1`.

The repository contains no separate executable real-time inference pipeline
beyond this 24-hour demonstration and the new model-only Android benchmark.
The 24-hour scripts also disagree about data provenance: `infer_24h.py` says
there is no ground-truth volume and describes a free-living session, whereas
`plot_24h_150ml_analysis.py` calls the same captures a fixed 150 mL phantom.
That provenance must be resolved before these results are reported.

## Exact wearable pipelines

### A. Legacy-compatible pipeline

This is the path that reproduces the released checkpoints and paper metrics:

1. Parse six physical traces and divide amplitude by 1700.
2. Apply piecewise exponential TGC with coefficients 0.15 and 0.4.
3. Apply a seventh-order 1.5--4.5 MHz Butterworth band-pass at 20 MSPS.
4. Clip to `[-0.1, 0.1]`.
5. Crop raw indices `[300:3000]`.
6. Form `mean(S2, S3)` and reorder to `(H_left, H_virtual, H_right, S1..S4)`.
7. Smooth the `(3, 2700)` H and `(4, 2700)` S arrays with `axis=0` separately.
8. Downsample by 10 and retain the first 220 samples.
9. Standardize each channel over those 220 samples.
10. Fill positions 220--399 with that channel's final-30-sample mean.

### B. Intended time/depth-axis pipeline

This audit changes only step 7 to `axis=1` and leaves every other operation
fixed. It is a sensitivity experiment, not a corrected checkpoint. The current
models were not trained on these inputs.

## Existing 24-hour output concordance

The saved 24-hour CSV agrees with the reproduced `axis=1` path to within
0.039 mL across all seeds. Against `axis=0`, mean absolute differences were
33.433, 35.529, 33.583, and 33.143 mL for seeds 1, 2, 3, and 42. The largest
per-seed differences were 102--125 mL. Therefore the existing live
demonstration is an `axis=1` result and is not preprocessing-compatible with
the final training/evaluation pipeline.

## Manuscript discrepancies

The current Methods text describes a sixth-order filter, a single TGC
coefficient of 0.1, clipping at phantom-wall onset, and padding before
standardization. The implementation uses a seventh-order filter, piecewise
0.15/0.4 TGC, fixed amplitude clipping followed by `[300:3000]` cropping,
standardization before tail-mean padding, and unreported channel-axis Gaussian
smoothing. Describing the wearable operation as depth-axis smoothing would be
incorrect for the released results. The clinical transform also uses `axis=0`
despite the manuscript's depth-axis language.

## Required decision

The lowest-risk path for preserving the existing checkpoints and reported
tables is to document the actual legacy-compatible implementation, change live
inference to `axis=0`, and regenerate the 24-hour predictions and figures after
resolving whether the session was free-living or a fixed 150 mL phantom.

If time/depth smoothing is the intended method, the current checkpoint metrics
cannot be retained. At minimum, all four DER++ Stage-2 seeds must be retrained
and re-evaluated. If the clinical pipeline is also corrected to `axis=1`, the
Stage-1 clinical model, all Stage-2 strategies and ablations, cross-domain
tables, attribution analyses, and figures must be regenerated. This is a full
paper experiment refresh, not an inference-only patch. No retraining was
started by this audit.
