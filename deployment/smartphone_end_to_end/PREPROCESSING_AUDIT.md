# Wearable RF preprocessing audit

## Status and scope

This is the read-only audit completed before implementing Android raw-RF
preprocessing. The authoritative behavior is the dataloader and evaluation path
that produced and evaluated the frozen DER++ seed-3 artifact. Existing prose and
the separate 24-hour prototype were treated as secondary evidence.

No checkpoint, ONNX model, quantization setting, split, test membership, or
manuscript TeX file was changed during this audit.

## Raw file format

- Data root: `<WEARABLE_DATA_ROOT>`
- Model cohort folders: `50/`, `150/`, and `300/`, each containing 100 text files.
- Every audited cohort file contains exactly 30,720 numeric comma-separated
  values, with no invalid token and no remainder after division by six.
- Every file therefore contains six contiguous traces of 5,120 samples.
- Source text is parsed as decimal numbers and converted to NumPy `float32`.
- Physical trace order is `[S1, S2, S3, S4, H_left, H_right]`.
- The current Python parser removes apostrophes and spaces, splits on commas,
  silently drops nonnumeric tokens, and derives the trace length by floor
  division. The released cohort does not exercise that permissive behavior.
  Android should reject invalid tokens, a non-divisible count, a channel count
  other than six, or a trace length other than 5,120.

## Exact released wearable pipeline

### 1. Parse and amplitude scaling

The six contiguous traces are reshaped to `(6, 5120)` and stored as `float32`.
Each physical trace is divided by `1700.0` and assigned into a `float32` array.

### 2. Piecewise exponential TGC

For sample index `n`, the depth in millimetres is

```text
d[n] = n / 20,000,000 * 1,500 / 2 * 1,000
```

For a 5,120-sample trace, the exact split index is `5120 // 2 = 2560`:

```text
TGC[n] = exp(0.15 * d[n] / 10),  0 <= n < 2560
TGC[n] = exp(0.40 * d[n] / 10),  2560 <= n < 5120
```

`d` and the concatenated TGC vector are `float32`, and multiplication is
performed in place on the `float32` RF array. This is not a continuous
piecewise curve: the coefficient changes at the midpoint while absolute depth
is retained. The audited TGC values are 4.218323 at index 2559 and 46.525478 at
index 2560. This discontinuity must be reproduced for checkpoint compatibility.

### 3. Butterworth band-pass filtering

- Sampling rate: 20 MHz
- Design: `scipy.signal.butter`
- Order: 7
- Band: 1.5--4.5 MHz
- Type: digital band-pass
- Representation: transfer-function numerator/denominator (`b`, `a`), not SOS
- Filtering: `scipy.signal.filtfilt` independently on each physical trace
- `filtfilt` defaults: `axis=-1`, `padtype='odd'`, `padlen=None`,
  `method='pad'`, and `irlen=None`
- For the 15-tap `a`/`b` arrays, the effective default edge extension is 45
  samples.
- Initial conditions are the padded-signal endpoint-scaled steady-state values
  generated internally from `lfilter_zi`; no persistent filter state is carried
  between channels or measurements.
- SciPy returns a floating-point result using the double-precision coefficients;
  every filtered trace is explicitly cast back to `float32` on assignment.

Coefficients generated by SciPy 1.15.1:

```text
b = [
  0.0009628940476967194, 0.0, -0.006740258333877035, 0.0,
  0.020220775001631105, 0.0, -0.03370129166938518, 0.0,
  0.03370129166938518, 0.0, -0.020220775001631105, 0.0,
  0.006740258333877035, 0.0, -0.0009628940476967194
]
a = [
  1.0, -6.453395330000912, 20.913214038490448,
  -44.949286859709844, 71.45464796016648,
  -88.59231588623601, 88.05843254742703,
  -71.10446812961118, 46.806571375594096,
  -24.98830436639225, 10.658709904313934,
  -3.5303740116686915, 0.8623915685376176,
  -0.14017787154703928, 0.011662728049189596
]
```

### 4. Clipping and crop

Filtering is followed by amplitude clipping to `[-0.1, 0.1]`. The clipped
physical traces are then cropped with Python slice `[300:3000]`, retaining raw
indices 300 through 2999 and producing `(6, 2700)`. Clipping therefore occurs
before cropping. Filter computation uses the full 5,120-sample trace.

### 5. Virtual channel and logical order

The virtual horizontal channel is calculated in `float32` as
`mean(S2, S3)` after filtering, clipping, and cropping. The model order is

```text
[H_left, H_virtual_mean_S2_S3, H_right, S1, S2, S3, S4]
```

The dataloader returns the first three channels as the horizontal group and the
last four channels as the sagittal group.

### 6. Gaussian operation

No Hilbert envelope is applied to the released wearable path. The horizontal
`(3, 2700)` and sagittal `(4, 2700)` arrays are processed separately using

```python
scipy.ndimage.gaussian_filter1d(group, sigma=1, axis=0)
```

Unspecified SciPy 1.15.1 defaults are `order=0`, `mode='reflect'`, `cval=0`,
and `truncate=4.0`. The effective radius is four. Critically, `axis=0` is the
within-group channel axis, not the sample/depth axis. An Android implementation
must not smooth all seven channels as one group because that would mix the
horizontal and sagittal boundary. It must reproduce two independent reflected
channel-axis operations of lengths three and four.

This axis is retained for compatibility with the trained checkpoint even though
sample-axis smoothing would be the more conventional interpretation. The
separate 24-hour prototype's `axis=1` behavior is not authoritative here.

### 7. Downsampling and truncation

Every group is downsampled on the sample axis with `[:, ::10]`, starting at
offset zero of the cropped signal. The 270 candidates are then truncated to the
first 220. Thus model sample `k` before standardization derives from cropped
sample `10*k`, corresponding to raw index `300 + 10*k`, for `k=0..219`.

### 8. Per-channel standardization

Each of the seven 220-sample channels is standardized independently:

```text
z = (x - mean(x)) / (std(x, ddof=0) + 1e-8)
```

The released implementation uses NumPy's population standard deviation
(`ddof=0`), adds `1e-8` unconditionally, and writes into a `float32` output
array. A constant finite channel therefore maps to zeros. The dataloader checks
the processed group for non-finite values after transformation, but the parser
and transform do not otherwise sanitize NaN or infinity.

### 9. Tail-mean padding

Standardization precedes padding. For each channel, the mean of standardized
positions 190 through 219 is repeated into positions 220 through 399. Padding
is not zero padding and is independent for every channel. The final model input
is contiguous `float32` with shape `(7, 400)`; Android inference adds the batch
dimension to form `(1, 7, 400)`.

## Split and golden-reference policy

The wearable split is deterministic and volume stratified with
`random_state=42`:

| Partition | Per volume | Total |
|---|---:|---:|
| Train | 64 | 192 |
| Validation | 16 | 48 |
| Held-out test | 20 | 60 |

The existing Android test manifest exactly matches the held-out partition and
its ordering. Android preprocessing development and stage-level parity will use
validation samples only. The predeclared first validation samples are
`50_30.txt`, `150_30.txt`, and `300_30.txt`. Held-out raw-RF evaluation will be
performed only after the Android implementation and tolerances have been frozen
from validation parity.

## Independent reconstruction check

An independent stage-by-stage reconstruction of validation sample `50_30.txt`
was compared against `deployment.dataset.load_preprocessed_partition`. The final
`(7,400)` arrays were bitwise equal with maximum absolute difference 0.0. All
seven padding regions were constant and equal to their own final-30-sample
means.

## Numeric environment

The frozen deployment metadata records Python 3.10.16, NumPy 2.1.2, SciPy
1.15.1, PyTorch 2.6.0, and ONNX Runtime 1.23.2. Golden references must be
generated with `<USER_HOME>/anaconda3/envs/torch310/bin/python`; the system
Python lacks PyTorch and ONNX Runtime and is not authoritative.

## Android implementation risks identified by the audit

1. Replacing `filtfilt` with a causal streaming IIR changes both phase and edge
   behavior and will not reproduce the checkpoint input.
2. Direct-form seventh-order band-pass filtering is numerically sensitive.
   Android must use the frozen double-precision `b`/`a` coefficients and match
   SciPy's odd reflection and forward/backward initial-state handling before
   casting to float.
3. Gaussian processing must be performed across channels separately within the
   3-channel horizontal and 4-channel sagittal groups.
4. The TGC coefficient switch at index 2560 is discontinuous and must not be
   "corrected" during deployment.
5. Downsampling starts at cropped offset zero, and only 220 of the 270 available
   points are retained.
6. Standardization uses population variance and occurs before nonzero
   tail-mean padding.
7. The released Python parser is permissive, but the Android path should fail
   explicitly on malformed input rather than silently shifting channel
   boundaries.
